## Objetivo
Gravar em vídeo o jogo novo até o Pikachu e trocar os nomes padrão: o jogador passa a ter o
nome da IA que está jogando (CLAUDE, quando é o Claude Code) e o rival vira GEMINI.

## Problemas e soluções

### 1. Vídeo da partida
- **Sintoma:** não havia como mostrar a partida, só screenshots soltas.
- **Causa:** o emulador só renderiza o último frame de cada ação.
- **Solução:** um script fora do pacote troca o `tick` do PyBoy por um que renderiza todo frame e
  manda o frame para o ffmpeg (60 fps, ampliado 4×). O `tick` do PyBoy é só leitura (Cython),
  então o script usa um objeto que repassa o resto para o PyBoy.
- **Evidência:** vídeo de 10.460 frames (2 min 54 s) até "received a PIKACHU", com a party final
  `[PIKACHU Lv5]`.

### 2. Digitar nomes na tela de nomes
- **Sintoma:** o jogo novo só sabia escolher os nomes prontos (YELLOW / BLUE).
- **Causa:** a tela de nomes é um teclado de letras, e não havia código para ele.
- **Solução:** `newgame.py`. O teclado está na `wTileMap` como texto (layout do
  `UpperCaseAlphabet` do pret), e o ▶ marca a letra atual. Para cada letra, o código lê a posição
  do ▶, anda até a letra, aperta A e no fim aperta START. Nomes aceitos: 1 a 7 letras A–Z
  (`PLAYER_NAME_LENGTH EQU 8` no pret, com o terminador). Nova tool MCP `new_game(player_name,
  rival_name="GEMINI")`, que valida os nomes antes de ligar o emulador.
- **Evidência:** `test_new_game_types_custom_names` (ROM): jogador CLAUDE, rival GEMINI, no
  quarto com controle livre. No vídeo, o Oak diz "His name is GEMINI!".

## Decisões
- O nome do jogador é o da IA que joga. Nos benchmarks da Fase 2, cada modelo joga com o seu nome,
  e o rival continua GEMINI.
- O vídeo ainda é um script avulso. Vai para o pacote quando houver run gravado de IA para virar
  vídeo.
